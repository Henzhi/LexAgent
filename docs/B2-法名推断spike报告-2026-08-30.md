# B2 法名推断 spike 报告——法名向量最近邻（2026-08-30）

> 结论：**采用条文质心法**（Recall@3 70.3%，达标 Go），否决描述文本法。
> 端到端接入（B2 第二阶段）待做，接入设计与验证判据见 §6。

---

## 1. 背景与动机

8/30 广覆盖评测（`e102acf`）揭示系统高度依赖「法名」信号；B1 修正了度量口径后，
当前事实（colloq148 集 = LLM 生成的**无 法名**真实口语，148 条覆盖 148 部法律）：

| 现状 | 数值 |
| :--- | ---: |
| 无 法名口语 PROD Hit@5 | 73.0%（Hit@1 49.3%，MRR 0.598） |
| precise（带法名+条号）Hit@5 | 97.5%（已近上限） |
| 法名缺失的代价 | Hit@1 掉 14 个点 |

**B2 价值定位**（经 B1 修正）：不是"救 6.7%"（那是规则模板病句集的假象），
而是把 73% 推向 precise 水平——手段：查询无法名时先**推断候选法名**，作为软信号
增强检索。

**约束**：推断必须零 LLM 成本（预算敏感：实测 18~20 次 LLM/复杂查询）、
在线零额外模型调用、软信号（绝不硬过滤——推断错了整路丢失）。

## 2. 候选方案与实现方式

两个变体共用同一评测框架（`eval_law_name_inference.py`），差别只在
"每部法律如何变成一个向量"。

### 变体 A：描述文本法（`build_law_name_index.py`）

**实现**：每部法律构造一段"描述文本"再 embed：

```
中华人民共和国刑法(2023修正) 刑法 首要分子 聚众 武装部队 受贿罪 …
```

- 描述文本 = 法名全称 + 简称 + **TF≥2 核心概念词 top14**（复用
  `generate_broad_queries.py` 的 `pick_keywords`/`build_law_df`：law DF 稀有度
  + 条文内 TF≥2 + 名词性词性过滤，8/29 调优过的"核心概念"逻辑）；
- 每法最多抽 40 条条文做关键词抽取（碎片过滤与 broad 生成器同口径）；
- `_create_embedder()`（bge-m3，与查询同一向量空间）批量 embed → L2 归一化
  → `law_name_index.npz`（881×1024）+ JSON 元数据；
- 离线成本：881 次 embed，30.6s。

### 变体 B：条文质心法（`eval_law_name_inference.py --mode centroid`）

**实现**：每部法律的向量 = 其全部 article chunk 向量的均值（质心）：

- **直接复用 PG 里已有的 5 万条 article chunk 向量**（入库时由 LawEmbedder
  生成，与查询向量同空间同分布）——零 embed、零离线索引文件；
- SQL `fetchmany` 拉取 → Python 按法累加均值 → L2 归一化 → 913×1024；
- 离线成本：SQL 拉取 + 解析 ≈ 几十秒，且可物化为 PG 小表随入库增量维护；
- 在线成本：查询向量是主检索本来就要算的，+1 次 913×1024 点积 ≈ 微秒级。

### 评测方法

- 评测集：colloq148（gold 条文 by construction，法名归一化匹配）；
- 流程：查询 embed → 与全部法律向量点积（余弦）→ gold 法名的排名；
- 指标：Recall@1/3/5/10、MRR；随机基线 Recall@1 ≈ 0.11%（约 900 部法律）；
- **go/no-go 判据（spike 前约定）**：Recall@3 ≥ 60% 才做端到端接入验证。

## 3. 结果对比

| 指标 | 变体 A：描述文本法 | 变体 B：条文质心法 | 差值 |
| :--- | ---: | ---: | ---: |
| 法名库规模 | 881 部 | 913 部 | — |
| Recall@1 | 29.1% | **39.2%** | +10.1 |
| Recall@3 | 51.4% | **70.3%** | +18.9 |
| Recall@5 | 63.5% | **78.4%** | +14.9 |
| Recall@10 | 77.7% | **87.2%** | +9.5 |
| MRR | 0.4364 | **0.5661** | +0.130 |
| 离线成本 | 881 次 embed（30.6s）+ npz 文件 | **零**（SQL 聚合已有向量） | — |

**变体 B 全指标大幅胜出，Recall@3 70.3% ≥ 60% go 线，判定 Go。**

## 4. 为什么质心胜出（归因分析）

1. **分布一致性**：质心是真实条文内容在 bge-m3 空间中的分布中心，与查询向量
   （自然语言）"同分布"；描述文本是"法名+关键词"的合成拼接，其嵌入分布与
   真实查询存在系统性偏移（bge-m3 对合成短文本的语义压缩方式不同）。
2. **关键词抽取有损**：每法只采样 ≤40 条条文（刑法 400+ 条只看 40 条），
   TF≥2 过滤在子集上失真，关键词覆盖不全——描述文本天然带着这份噪声。
3. **覆盖面差**：质心法 913 部 vs 描述文本法 881 部（后者在碎片过滤阶段
   多淘汰了关键词不足的小法）。

## 5. 最终选型

**采用变体 B（条文质心法）**，理由按权重排序：

1. 精度显著更高（@3 +18.9 点，是达标与否的差距）；
2. 成本更低：零 embed、零离线索引文件、无关键词抽取链路依赖（少一层维护）；
3. 实现更简单：一个 SQL 聚合；来源单一（主库向量），主库重 embed 后质心
   随之更新，不会漂移。

变体 A 的产物保留（`build_law_name_index.py` + `law_name_index.npz`）作为
对照基线，不删除——将来若做"法名+章节结构"的描述增强可在此基础上迭代。

**转正形态（端到端接入时落地）**：质心物化为 PG 小表
`law_centroids(law_name, vector, n_chunks, updated_at)`，随入库任务增量更新；
在线检索链启动时加载一次（913×1024 ≈ 3.7MB 内存），每请求一次点积。

## 6. 端到端接入实验（B2 第二阶段）——**NO-GO，已回退**

接入已实现并实测（`src/rag/law_name_boost.py` + `src/rag/law_centroids.py`，
接入点 Rerank 之后 Adjacent 之前，配置 `LAW_NAME_BOOST_*` 默认关闭）：

| 配置 | colloq148 Hit@5（基线 73.0%） | multi100 Hit@5（基线 92.0%） |
| :--- | ---: | ---: |
| boost=0.1, top3 | 66.9%（**-6.1**） | 85.0%（**-7.0**） |
| boost=0.03, top3 | 70.9%（-2.1） | — |

伤害随 boost 单调递增；逐条 diff（丢失 13 / 新增 4）显示错误法名上浮
挤掉 gold（如"私自买卖制毒原料"刑法350 条被质心推上来的禁毒法64 条挤掉）。

### 三次归因排查

1. **置信门控无效**：gold 在/不在 top3 两组的 top1 相似度分布几乎重叠
   （中位 0.647 vs 0.634，margin 0.045 vs 0.034）——质心相似度绝对值
   无法区分"推断可信/不可信"；
2. **⭐ 根本原因：信号同源**——质心向量与主检索向量都是 bge-m3 的产物，
   质心加权的信息是主检索已用信息的子集，**不提供正交增益，只注入噪声**；
   且质心推断自身 21.6% 的错误率 × rerank 头部间隔仅 0.007~0.025，
   任何有效幅度的 boost 都会让 22% 的查询错误横跳；
3. **单标注计分放大损失**：多标相关法（禁毒法 vs 刑法 350）互换名次
   在单标注集上计为 miss——这部分是度量摩擦，但即使按多标口径，
   错误上浮仍是净伤害。

### 结论与正确用途

- **作为检索加权信号：NO-GO**（`LAW_NAME_BOOST_ENABLED` 默认 false 保持，
  代码保留——若将来有正交的法名信号源如 LLM 改写/独立分类器，接入点可复用）；
- **作为"法名推断"本身有效**（Recall@3 70.3%）：可用于面向用户的
  "你可能想问的是关于《XX法》的问题"提示、未来 M4 agent 的 plan 信号
  （C1 plan 对象的检索约束）、以及查询日志分析——这些场景不与主检索
  信号叠加，不存在同源噪声问题；
- **要在无法名查询上真实提升检索（73%→80%+），必须引入正交信号**：
  LLM 查询改写（生成规范表述+法名）、同义词词典扩展、独立法名分类器——
  按成本排序优先试查询改写（基建已有 /rewrite）。

### 流程教训（已入 E-02 复发清单精神）

"spike 达标（离线 Recall）≠ 端到端达标"——离线推断指标测的是信号质量，
端到端加权测的是**信号的边际价值**；同源信号的边际价值趋零。
负结果同样入库：本次实验链（代码 + 三组数据 + 归因）完整保留。
