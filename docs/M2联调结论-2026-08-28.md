## 2. 双路径口径（重要：前端与测试必读）

流式 `/api/chat/stream` 与非流式 `/api/chat` 的来源字段**口径完全一致**，均为融合后的 `fused_sources`：

- **条数**：最多 `FUSION_TOP_K=8` 条（去重 + 来源加权排序后截断）
- **字段**：每条来源包含以下字段——

| 字段 | 说明 | 流式 / 非流式 |
| :--- | :--- | :--- |
| `law_name` | 法名或文章标题 | 两者一致 |
| `citation` | 引用（法名 · 条号） | 一致 |
| `content` | 条文 / 摘要原文 | 一致 |
| `score` | 原始相关度分（0~1） | 一致 |
| `source` | `internal_kb` / `legal_source` / `web` | 一致 |
| `verification` | 四态验证状态（见下） | 一致 |
| `url` | 官方源 / 网络结果的链接 | 仅融合结果有 |
| `law_status` | 法规状态（现行有效等） | 仅官方源有 |
| `superseded` | `true` = 网络信息与内部库冲突，以内部库为准 | 仅 web 有 |

**前端约定**：字段可能缺失（旧会话历史数据、固定管线路径），渲染时一律做判空，缺失时不显示徽章。

**测试约定**：断言两条路径的 `verification` 分布一致，断言非流式不再返回无 `verification` 的原始检索文档（回归：`tests/test_chat_response_sources.py`）。

## 3. verification 四态与渲染约定

| verification | 含义 | 徽章文案 | 颜色 | 前端展示 |
| :--- | :--- | :--- | :--- | :--- |
| `verified_internal` | 内部法律知识库已验证 | 内部库 | 绿（`--color-success`） | 可直接作为法律依据 |
| `verified_official` | 官方源（国家法律法规数据库 / 案例库）已验证 | 官方源 | 蓝（`--color-primary`） | 权威已验证 |
| `third_party` | 第三方数据源（小包公，未采购暂不出现） | 第三方 | 橙（`--color-warning`） | 建议回源核验 |
| `web_unverified` | 网络搜索线索，未经验证 | 网络未验证 | 灰（text-secondary） | 仅供参考 |

**渲染规则**（`ChatMessage.vue` 已实现）：

1. 每条来源右侧显示徽章，hover 显示说明（`title` 属性）
2. 折叠标题栏显示来源构成汇总，如「6 内部库 · 2 网络未验证」，按可信度排序
3. 含 `third_party` / `web_unverified` 时列表顶部显示警示条：「含 N 条未经官方源验证的线索，仅供参考，不宜直接作为法律依据」

**回答正文**中的「（来源：内部知识库）」文字标注由提示词约束 LLM 生成（F10），与徽章互为补充，不冲突。

## 4. 配额策略（后端逻辑，测试需知）

`fusion.py::fuse_evidence()` 的截断策略（D-M3-4）：

- 三路证据按 `fused_score` 排序：内部库（1.0×(0.5+0.5×score)）> 官方源（0.85）> 网络（0.5×tavily_score）
- **网络线索保底配额** `FUSION_WEB_MIN_SLOTS=2`：网络先占 `min(配额, 网络条数, top_k)` 个位置，其余名额给权威来源；权威不足时用剩余网络补满；最终仍按分排序，权威展示在前
- 设 `FUSION_WEB_MIN_SLOTS=0` 可退化为纯按分截断（网络可能一条不剩）

**为什么需要配额**：网络权重天然低于权威来源，纯按分截断时 `top_k=8` 一旦被内部库 + 官方源填满，网络线索一条都不剩——Tavily 调用成本照付，用户却完全看不到，`web_unverified` 状态形同虚设。

**测试关注点**（已有回归：`tests/test_fusion.py::TestWebQuota`）：

- 权威条数 ≥ top_k 时，网络线索仍保底 2 条
- 网络线索不足 2 条时全部保留，不浪费位置
- 无网络线索时行为与纯按分截断完全一致
- 配额不破坏优先级：权威来源仍排在网络之前
