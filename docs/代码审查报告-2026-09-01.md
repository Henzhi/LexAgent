## 📊 总体评估

### 健康度评分：**6.5 / 10**

加分项（工程底子扎实，超出多数同类项目）：
- 文档体系（AGENTS.md / DECISIONS.md / CHANGELOG.md）质量高，历史 Bug 与决策依据均有记录

扣分集中在**安全边界与资源管理**——功能正确，但"谁能调用、调用多少次、占用多少连接"这层没守住。

## 🔧 优化方向

### 1. 性能优化

- **引入连接池（最优先）**：14 处裸 `psycopg2.connect`，其中 `auth.py:98` 每次 token 验证都新建连接。改用 `psycopg2.pool.ThreadedConnectionPool`，`minconn=2 / maxconn=20`。同时 `pgvector_store.py` 与 `conversation_store.py` 的「单连接 + `threading.Lock`」模型把所有 DB 操作串行化，是当前最大的并发瓶颈——高并发下锁竞争比查询本身更耗时。
- **预算计数改原子操作**：`cost_budget.py:156-203` 的 `check()`（GET）与 `record()`（INCRBY）是两次独立往返，存在 TOCTOU——并发 N 个流可同时通过检查。改用 Lua 脚本（INCR → 与 limit 比较 → 超限则 DECR 并报错），或直接用 INCR 返回值判断。
- **前端流式渲染节流**：`ChatView.vue:375-376` 每个 token 都 `await nextTick()` + 读 `scrollHeight`（强制同步布局）。长回答下 DOM patch 与重排次数 = token 数。改用 `requestAnimationFrame` 节流，或每 3~5 个 token 刷一次。
- **会话保存增量**：`ChatView.vue:394` 每轮结束上传整个 messages 数组，历史越长 payload 越大。改为追加增量。

### 2. 安全性加固

- **鉴权缺口统一收口**（对应上表 3 条高危）：建立路由级 checklist，区分 `get_current_user`（软，回退匿名）与 `require_registered_user`（硬，401），逐个路由核对并在文档中同步。
- **Token 迁移出 localStorage**：`frontend/src/api/index.js:4`、`stores/auth.js` 明文存 JWT，任何 XSS 可直接窃取。改 HttpOnly + Secure + SameSite=Strict Cookie。
- **补 401 全局处理**：`api/index.js` 加响应拦截器，401 时 `auth.logout()` + `router.replace('/login')`。当前路由守卫只校验 token 是否存在，token 过期后用户停留在页面但列表/历史全部静默失败（`ChatView.vue:226,247` 是空 `catch`）。
- **预算 check 与 record 的原子化**（同性能优化第 2 条，既是正确性也是成本安全问题）。
- **工具参数白名单**：工具参数是 LLM 生成的，等同于不可信输入。当前只有发给模型的 schema 里有约束，运行时不强制。

### 3. 代码质量与可维护性

- **为熔断相关逻辑补回归测试**：当前 607 个测试跑得快但覆盖偏功能正确，缺少「预算超限必须中断」「鉴权路由必须 401」这类守护型断言——本次两个高危问题都属于有测试也不会红的类型。✅ **已补**（`eb29ea5` 8 项 + `971042f` 3 项守护测试）
- **删除死代码**：`src/llm/client.py`（392 行）、根 `package.json`（`docx`/`pptxgenjs` 全仓库无 JS 引用）、`retry.py:33-41` 的重复分支、`base.py:38-52` 无调用的 `to_message()`。◐ **部分完成**（retry 重复分支 + to_message 已删 `ddb6477`；client.py 与根 package.json 未删）
- **CI 补前端 job**：`.github/workflows/ci.yml` 只有 ruff + pytest（且 `--ignore=tests/test_api.py`），无 `npm ci`、无 `vite build`。前端改动零校验，构建失败不会在 CI 暴露。
- **自研 Markdown 渲染器换成熟方案**：`ChatMessage.vue:140-208` 目前 escapeHtml 覆盖完整、无注入点，但自研渲染器后续加「支持链接/表格」极易引入绕过。建议 `markdown-it` + `DOMPurify` 白名单。

### 4. 依赖与架构

- **Vite 5 已 EOL**：`frontend` 实际锁定 vite 5.4.x，其绑定的 esbuild 0.21.5 落在大批 dev-server CVE 范围内且无法单独升级。建议升 Vite 7（需回归 `build.outDir: '../static'` 位于项目根之外的行为，建议显式加 `emptyOutDir: true`）。
- **降级链路加可观测性**：当前 `failover` 降级后无任何指标暴露，运维不知道服务处于降级态。建议在 `/api/health` 暴露 `degraded` 状态与降级原因。
- **明确生产部署形态**：`Dockerfile:30` uvicorn 直曝 `--host 0.0.0.0`，无反代承载 HTTPS 与限流——这直接决定了上述鉴权缺口的实际暴露面，需要确认。
