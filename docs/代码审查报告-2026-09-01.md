## 📊 总体评估

### 健康度评分：**6.5 / 10**

加分项（工程底子扎实，超出多数同类项目）：
- 文档体系（AGENTS.md / DECISIONS.md / CHANGELOG.md）质量高，历史 Bug 与决策依据均有记录
- 流式架构设计专业：同步生成器隔离到 `ThreadPoolExecutor`，配合 watchdog + 主动 cancel flag + ASGI `http.disconnect` 三重机制，客户端断开能真正停止 Token 消耗
- 输入注入防御到位：`sanitize_input` 覆盖 query 与 history 两侧（history 过滤是很多项目会漏的点）
- 68 处 SQL 全部参数化；错误处理遵循"统计/监控故障不拖垮主链路"的一致原则

扣分集中在**安全边界与资源管理**——功能正确，但"谁能调用、调用多少次、占用多少连接"这层没守住。

## 🔧 优化方向

### 1. 性能优化（✅ 已全部完成 2026-09-03）

- ✅ **引入连接池（最优先）**：14 处裸 `psycopg2.connect`，其中 `auth.py:98` 每次 token 验证都新建连接。改用 `psycopg2.pool.ThreadedConnectionPool`，`minconn=2 / maxconn=20`。同时 `pgvector_store.py` 与 `conversation_store.py` 的「单连接 + `threading.Lock`」模型把所有 DB 操作串行化，是当前最大的并发瓶颈——高并发下锁竞争比查询本身更耗时。（`260fd8c` 池基础设施 + auth/一次性直连接入；`19ec053` 池向量注册；`a5ac901`/`326d318`/`df348b5`/`af23587` 六个 store 类全部改每操作借用，全仓无裸 connect）
- ✅ **预算计数改原子操作**：`cost_budget.py:156-203` 的 `check()`（GET）与 `record()`（INCRBY）是两次独立往返，存在 TOCTOU——并发 N 个流可同时通过检查。改用 Lua 脚本（INCR → 与 limit 比较 → 超限则 DECR 并报错），或直接用 INCR 返回值判断。（`8aaf62d`：reserve/release 预占模型，拦截点移到花钱之前）
- ✅ **前端流式渲染节流**：`ChatView.vue:375-376` 每个 token 都 `await nextTick()` + 读 `scrollHeight`（强制同步布局）。长回答下 DOM patch 与重排次数 = token 数。改用 `requestAnimationFrame` 节流，或每 3~5 个 token 刷一次。（`e534f44`：rAF 合并，按帧滚动）
- ✅ **会话保存增量**：`ChatView.vue:394` 每轮结束上传整个 messages 数组，历史越长 payload 越大。改为追加增量。（`e534f44`：`mode=append`，服务端 SQL 内 JSONB `||` 拼接）

### 2. 安全性加固（✅ 已全部完成）

- ✅ **鉴权缺口统一收口**（对应上表 3 条高危）：建立路由级 checklist，区分 `get_current_user`（软，回退匿名）与 `require_registered_user`（硬，401），逐个路由核对并在文档中同步。（`971042f` 7 路由硬鉴权 + `388c959` 401 全局拦截；`tests/test_route_auth_guard.py` 守护）
- ✅ **Token 迁移出 localStorage**：`frontend/src/api/index.js:4`、`stores/auth.js` 明文存 JWT，任何 XSS 可直接窃取。改 HttpOnly + Secure + SameSite=Strict Cookie。（`399caa7`：HttpOnly + SameSite=strict + 无鉴权幂等 logout 端点）
- ✅ **补 401 全局处理**：`api/index.js` 加响应拦截器，401 时 `auth.logout()` + `router.replace('/login')`。当前路由守卫只校验 token 是否存在，token 过期后用户停留在页面但列表/历史全部静默失败（`ChatView.vue:226,247` 是空 `catch`）。（`388c959`）
- ✅ **预算 check 与 record 的原子化**（同性能优化第 2 条，既是正确性也是成本安全问题）。（`8aaf62d`）
- ✅ **工具参数白名单**：工具参数是 LLM 生成的，等同于不可信输入。当前只有发给模型的 schema 里有约束，运行时不强制。（`c74c05b` 09-02 B4：执行前 `tool_call_schema` pydantic 校验）
