## 3. 核心隐患因果推理（Top 5）

### 隐患一：管理接口零认证 + history 注入缺口（P0）
- **现象**：`/knowledge/upload`、`/knowledge/documents/{id}`(DELETE)、`/crawl`（含 `subprocess` 重建索引）未挂认证依赖；`/chat` 仅过滤 `query`，`history` 原样注入。
- **诱因**：需求变更遗留。认证是后期版本叠加的，仅覆盖了"用户对话"主路，早期内部调试用的管理路由未回流补齐；`sanitize_input` 设计时未意识到多轮场景下历史消息同样是攻击者可控输入。
- **引爆条件**：服务暴露到非受信网络即引爆，无需并发门槛——单次请求即可删库；一条构造的 history 即可操纵模型输出。
- **连锁反应**：知识库被删 → 检索召回为空 → 阈值回退分支放行低分结果（`retriever.py:102-107`）→ 幻觉防御承压 → 用户得到编造的法条。法律咨询场景下这是误导性法律意见，可能致用户错过诉讼时效等不可逆损失。

### 隐患二：单连接 psycopg2 跨线程共享（P0）
- **现象**：4 个存储类在单例中各持一条物理连接；同步路由被 FastAPI 投入线程池并发执行（psycopg2 连接不可跨线程并发使用）。
- **诱因**：最初设计缺陷——从 FAISS 单机脚本迁移到 Web 服务时沿用了"脚本式单连接"心智。
- **引爆条件**：并发 ≥2 个会话操作请求；PG 负载高/慢查询时交错概率陡增。
- **连锁反应**：交错事务 → 会话消息写串（用户 A 对话出现在用户 B 历史，越权泄露）→ 连接 abort → 探活/重连竞态 → 重连风暴；且 `conn.dsn` 重连可能缺密码 → 记忆/FAQ 静默降级，用户感知"突然失忆"。

### 隐患三：`stream()` 绕过编译图的双轨漂移（P1）
- **现象**：`graph.py:192-263` 手动循环调用节点闭包；流式 casual 无 system prompt（`graph.py:154`）；意图识别绕过图节点；流式重试每次重新检索，与非流式语义不同。
- **诱因**：历史遗留——`stream()` 先于 LangGraph 图存在，图上线后流式路径未重构。
- **引爆条件**：非崩溃型，是维护性引爆——下次新增节点时改图忘改手写循环，且 `chat/stream` 测试覆盖为 0，无任何报警。
- **连锁反应**：幻觉防御/记忆检索节点在流式路径被旁路 → 面向用户的实际输出（流式）恰是防御最弱路径。

### 隐患四：每文档全量 REINDEX（P1）
- **现象**：`pipeline.py:143` 每文档入库后 `REINDEX INDEX idx_chunks_embedding`（锁表整表重建）。
- **诱因**：过度防御——用 REINDEX 兜底"写入后检索质量波动"，未意识到 HNSW 本就增量生效（模块 docstring 自述）。
- **引爆条件**：库规模 10 万+ 且批量导入 100 个文档时，100 次秒级锁表 = 导入窗口内检索长时间阻塞。
- **连锁反应**：导入与在线检索争抢同一连接（叠加隐患二）→ 检索超时 → 请求堆积 → 线程池耗尽 → 全站无响应。

### 隐患五：密钥与异常信息双重泄露（P0/P2）
- **现象**：`.env:4` 真实 `sk-` key 明文；PG 密码写死在 `config.py:148` 进 git；`main.py:101` 等 `detail=str(exc)` 直发客户端。
- **诱因**：开发便利优先的渐进累积；调试期友好实践上线前未切换双层错误模型。
- **引爆条件**：仓库误推送、协作者机器被入侵，或攻击者从异常原文拼出连接串结构+内网拓扑。
- **连锁反应**：key 泄露 → 计费盗刷 → 限流 → 线上问答全面不可用（双后端间无自动 failover）。
