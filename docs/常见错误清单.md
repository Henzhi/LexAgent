# 常见错误清单 — 复发错误知识库

> 目的：同类错误**不犯第二次**。改代码前扫一眼；犯错的瞬间对照这里；修完后回填新条目。
>
> **收录规则**：① 同类错误出现第二次；或 ② 一次性但属高危静默故障（不报错、难排查）。
> 单纯的外部服务波动（如 flk 接口改版）不收——那靠容错设计应对，见 AGENTS.md 架构约定。
>
> 条目格式：**症状 → 根因 → 预防**。新条目加在最上面，注明首次/复发日期。

---

## 工程/环境类

### E-13 本地/CI 的 Python minor 版本差异掩盖缺陷（2026-08-30，首次）
- **症状**：本地 718 全绿，CI 单测挂 tool docstring 缩进断言（`test_docstring_becomes_description`）。
- **根因**：本地 venv = Python **3.13.5**，CI = **3.12**（`requires-python>=3.12` + CI 固定装最低支持版）。**Python 3.13 起编译器自动去除 docstring 缩进，3.12 的 `fn.__doc__` 保留源码缩进**；LangChain `StructuredTool.from_function` 在 `parse_docstring=False` 时直接用裸 `__doc__` 作 description → 3.12 下多行工具描述带缩进发给 LLM。langchain-core/pydantic 版本两边完全一致，差异纯在编译器行为。
- **预防**：① 依赖 stdlib 编译/字符串行为的代码，按 `requires-python` 范围内**最低版本**的行为设计（CI 固定 3.12 是正确的——测的就是最低支持版）；② 遇到「本地绿、CI 红」先查 `python -V` 差异，用 Docker `python:<CI版本>` 复现（分钟级），别靠猜；③ Git Bash 下 `docker run -v` 要加 `MSYS_NO_PATHCONV=1`，否则容器路径被改写成宿主 Git 安装目录。


### E-12 删「看似死代码」前只查了调用点，没追运行时数据流（2026-08-30，首次）
- **症状**：清理 `_tool_calls_to_openai` 的多形态兼容时，grep 调用点推断「输入恒为 ToolCall」，删掉 dict 分支后 18 个测试失败——`_messages_to_dicts` 重建历史消息时，state 里的 assistant 消息经 `add_messages` reducer 转成 AIMessage，其 `tool_calls` 是 **LangChain dict 形态**（`{"name","args","id","type"}`），不是 ToolCall。
- **根因**：静态 grep 只能证明「谁调用了它」，证明不了「运行时数据长什么样」——数据形态由 LangGraph reducer 的转换行为决定，不在任何调用点的字面参数里。
- **预防**：删「兼容分支」前必须回答**每个分支的输入从哪来**：顺着数据流（state → reducer → 重建）追一遍，而不是顺着调用图追一遍；拿不准就先加 `assert isinstance` 观察一轮再删。测试全绿不能作为死代码判据（见 E-04）。

### E-11 ad-hoc 跑单测忘清 `TAVILY_API_KEY` → web_search 用例假失败误判（2026-08-30）
- **症状**：`uv run pytest tests/test_react_agent.py` 报 `tool_result.ok` 断言失败，误以为代码改坏了；全量跑又绿。
- **根因**：`.env` 里有真实 Key，被 config 读走，`web_search` 真的搜成功了；该用例断言的是「未配 Key → 搜索不可用」。
- **预防**：跑测试一律 `TAVILY_API_KEY= uv run pytest tests/ -q`（AGENTS.md 常用命令）。看到「只有 web/网络相关用例挂」先怀疑环境再怀疑代码。

### E-10 旧进程占端口 → 误判「修复没生效」（2026-08-28）
- **症状**：改了代码重启服务，行为依旧是旧的；连查几次都是旧进程的代码。
- **根因**：`TaskStop` 失败后旧 uvicorn 仍占 8000 端口，新服务启动失败但无显式报错，请求全打到旧进程。
- **预防**：重启服务前必须确认端口真的释放：`netstat -ano | grep :8000`。

### E-09 git push 静默失败（exit 1 无输出）→ GCM 弹 GUI 认证被沙箱杀（2026-08-29）
- **症状**：`git push` 无任何输出直接失败，看不到错误信息。
- **根因**：HTTPS remote 走 Git Credential Manager，想弹 GUI 认证窗口被沙箱杀掉；且本机 `HTTPS_PROXY=127.0.0.1`（Clash）连不上 github。
- **预防**：remote 用 SSH（`git@github.com:Henzhi/LexAgent.git`，已配置）；push 清代理变量：`env -u HTTPS_PROXY -u HTTP_PROXY git push`。遇静默失败先 `git -c credential.helper= -c core.askPass= push` 让错误显形。

### E-08 依赖安装「假成功」：新包装上、旧 dist-info 没删（2026-08-29）
- **症状**：`ImportError: cannot import name 'ModelAPIError' from 'langchain_core.exceptions'`；`uv pip install` 报 "Uninstalled 2 / Installed 4" 但实际没卸干净。
- **根因**：沙箱 safe-delete 拦截文件删除（`windows-sandbox-recycle-bin-unavailable`），卸载步骤静默失败，残留空壳 dist-info。
- **预防**：装依赖/lock 一律清环境变量绕过 shim：`env -u CODEBUDDY_MCP_CONFIG -u CODEBUDDY_SESSION_ID -u CLAUDE_SESSION_ID uv lock`（shim 检测到这些变量为空就直接透传真命令）；`uv run` 遇 lock 不一致用 `--frozen` 临时绕开。

### E-07 提交前不跑 ruff → CI 必卡 F401（2026-08-27 首犯，2026-08-30 pkulaw 提交复发）
- **症状**：CI 红灯 `typing.Any imported but unused`，本地测试全绿。
- **根因**：本地只跑了 pytest 没跑 lint；unused import 多产生于重构后删代码、或复制模板没清理。
- **预防**：提交前固定动作 `TAVILY_API_KEY= uv run ruff check src/ tests/ && uv run ruff format --check src/ tests/`（已进 CI，本地跑一遍再 push）。

## 代码/架构类

### E-14 用 LangChain Tool 的 `invoke()` 直调 executor → 结构化结果被拍平（2026-09-02，D-0902-5）
- **症状**：`langchain_tool.invoke(arguments)` 包装 executor 时，返回的 `ToolResult` 数据类被 `BaseTool.run` 的「非字符串返回值 str() 化」拍成一行字符串——上层以为拿到结构化结果（tool/call_id/summary/data），实际全丢，且不报错。
- **根因**：误以为「带 pydantic 的 invoke = 校验 + 执行」一步到位；LangChain 的 Tool 层是为「把工具结果文本喂回模型」设计的，不为项目自有的结构化结果契约服务。
- **预防**：**校验用 schema、执行仍走 `spec.executor()`**——`tool_call_schema.model_validate(arguments)`（ValidationError → 「参数校验失败」）后 `executor(**validated.model_dump())`（registry.py `_invoke_validated` 即标准实现，D-0902-5）；不要直接调 `langchain_tool.invoke()` 代替 executor。

### E-06 绕过公开入口/框架机制 → 横切语义静默丢失（2026-08-28 首犯；2026-08-30 D-M3-14 复发）
- **症状 1**：流式路径手写 `while` 步进节点 + `dict.update()` 合并状态 → messages 配对破坏，DeepSeek 400 降级 Ollama（D-M2-6/D-M3-1）。
- **症状 2**：`agent_node` 直接 `chat_model.bind_tools().invoke()` → 重试（429/5xx）与 Failover 4xx 降级同时失效，测试全绿无人发现（D-M3-14）。
- **根因**：「标准写法」「自己实现更可控」的冲动，绕过了入口链路上承载的横切职责（重试/降级/预算/消息配对）。
- **预防**：LLM 调用必须走 `chat_with_tools()` 公开入口、图执行必须走编译图让 reducer/条件边各司其职；**绕过任何公开入口前，逐项核对该入口承载的横切职责**并在 DECISIONS 留痕。

### E-05 协程漏 await → 零报错静默故障（2026-08-30，pkulaw `_discover`）
- **症状**：`_tool_map` 恒空、静默退化到兜底工具名，所有真实调用失败，无任何异常与日志。
- **根因**：`self._discover(session)` 少 `await`，协程从不执行；Python 对未 await 协程只发 `coroutine was never awaited` 运行时警告（被吞），不抛错。
- **预防**：涉及协程的调用点，测试必须断言**副作用已生效**（如映射非空），而不是只断言返回值；新 async 路径上线前真链路探一次。

### E-04 Fake 替身抹平真实路径的不对称性 → 回归测试漏网（2026-08-30，D-M3-14 的帮凶）
- **症状**：`FakeToolLLM` 的假 ChatModel 内部委托回 `chat_with_tools`，导致「走公开入口」与「绕过入口」两条路径在测试里等价，绕过入口的回归全绿存活。
- **根因**：替身为了「让既有测试不改动」实现得太聪明，掩盖了两条路径的真实差异。
- **预防**：替身要与被测真实路径保持**同样的结构差异**；关键横切语义（重试/降级/熔断）的测试要穿透到真实入口（如 `TestAgentNodeCallSemantics` 用「只在 `_chat_with_tools_impl` 应答」的假后端，绕过入口必失败）。

### E-03 LangChain 不认识自研 schema 类 → description/enum 静默丢弃（2026-08-29，`Param` 类）
- **症状**：发给模型的工具 schema 缺少参数描述与枚举引导，不报错、极难发现。
- **根因**：LangChain 只认自己的注解元数据（`Annotated` + `Literal`/`Field`），自定义类直接忽略。
- **预防**：枚举一律 `Literal[...]`（AGENTS.md 代码规范已有）；新增注解写法后用 `registry.langchain_tools()[i].args_schema` 实际打印验证。

### E-02 检索层只看聚合指标 → 「救 6 丢 6」净零假象存活 26 天（2026-08-29）
- **症状**：HybridRetriever w=3.0 在语义集上 Hit@5 聚合值与关闭时相同，实际「向量 top1 命中的 6 条被换成相邻条文」，聚合值掩盖劣化。
- **根因**：只验单一测试集 + 只看聚合值 = 盲区叠加；评测报告重跑时同名文件互相覆盖，破坏证据链。
- **预防**：检索层改动必须**逐条 diff + 语义集/法条级双集验证**（AGENTS.md 已沉淀）；评测报告文件名按配置区分（`prod`/`prod_nohybrid`/`bare`…）防覆盖。

### E-01 停用词/分词行为凭字面推测 → 误判（2026-08-29，「年月日」死代码、「万元」误删）
- **症状**：认为「年月日」「万元」都被误删会丢召回——实际「年月日」从未生效（jieba 把日期切散，该词作为整体从未产出）。
- **根因**：没跑一遍 jieba 看真实切分就下结论。
- **预防**：判断分词/停用词行为前，先对代表查询跑一遍真实 token 流；停用词表只放真正的虚词，有区分度的词交给 IDF。

## 评测/数据类

### E-00 单标注评测集系统性低估绝对值（2026-08-29 审计）
- **症状**：Hit@5 67% 被当作系统真实水平对外引用；抽查发现至少 3/12 未命中是「系统比标注更准」。
- **根因**：每条查询只标 1 条相关条文，覆盖 11/991 部法律，无 held-out。
- **预防**：**相对结论可信、绝对值当下界**；改进路径 = 多标注（2~5 条）> 留 held-out > 扩覆盖（已列 B1 任务）。
