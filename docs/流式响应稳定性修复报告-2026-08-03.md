# 流式响应稳定性修复报告

- 日期：2026-08-03
- 范围：`/chat/stream` 流式链路、LLM/Embedding 重试策略、前端 SSE 解析与取消、共享数据库连接并发安全
- 状态：已完成，全量测试通过

## 1. 背景与问题

线上出现五类与流式 AI 服务相关的典型故障，需要逐项排查：

| # | 现象 | 严重度 |
|---|------|--------|
| 1 | 用户等待 8 秒看不到第一个字，误以为卡死直接刷新页面 | 高 |
| 2 | 模型返回一半 JSON，前端解析失败，后端日志只有残缺的 `{"answer": "根因是。` | 高 |
| 3 | 供应商偶发 429，服务疯狂重试，越重试越被限流 | 高 |
| 4 | 用户点取消后浏览器已断开，后端仍在消耗 Token | 中 |
| 5 | 同一业务请求因重试执行两次，落库、扣费、发通知重复 | 高 |

经排查，五类问题在本系统**全部存在**，且相互关联，根因集中在三处：

1. **同步 LLM 调用阻塞事件循环**（问题 1、4 的共性根因）
2. **重试策略过于粗糙**（问题 2、3、5 的共性根因）
3. **取消信号不传播到 LLM 底层**（问题 4）

## 2. 根因分析

### 2.1 首字延迟（问题 1）

- `/chat/stream` 是 `async def`，但内部 `agent.stream()` / `llm.chat_stream()` 为**同步迭代**。模型生成期间整个事件循环被锁死，一个慢请求会拖垮所有请求。
- 首字前存在串行延迟链：短查询先发一次**完整**非流式 LLM 调用做意图路由（`needs_retrieval`）→ pgvector 检索 + CrossEncoder 精排（CPU 推理）→ 模型开始吐首 token。
- 前端在 `token` 事件前只有"思考中..."提示，长时间无字，用户自然判定卡死。

### 2.2 半截 JSON / 内容丢失（问题 2）

- 前端 `streamChat` 对 `JSON.parse` 失败**静默丢弃**（`catch { /* skip malformed */ }`），内容丢失无感知。
- 三个 LLM 后端（openai / ollama / 遗留 `client.py`）的流式实现，**流中途失败会从头重试整个流**——已发出的 token 重复输出，用户看到"答到一半又从头来"，且重复计费。

### 2.3 429 越重试越被限流（问题 3）

- 所有 LLM/Embedding 后端 `except Exception` 捕获**一切**异常重试：4xx 业务错误（必然失败）、429、5xx、网络错误一视同仁。
- 退避策略为固定线性 `retry_delay * attempt`，**无抖动**：多请求同时失败同时重试，惊群放大限流。
- 不读取供应商返回的 `Retry-After` 头。

### 2.4 取消不生效、Token 浪费（问题 4）

- 断开检测粒度粗：只在每个事件之间检查，模型生成期间无法中断。
- **无底层取消传播**：断开时底层 LLM 流不会被关闭，HTTP 连接不释放，模型继续生成消耗 Token。
- 同步阻塞导致断开检测本身要等下一个 chunk 返回才执行。

### 2.5 重复执行（问题 5）

- LLM 层重试无法区分"请求未送达"（可重试）与"请求已处理但响应丢失"（重试 = 重复扣费）。
- 流中途失败重试整个流 = 重复计费 + 重复内容。

## 3. 修复方案

### 3.1 统一重试策略（新增 `src/llm/retry.py`）

- `is_retryable(exc)`：429 / 5xx / 网络 / 超时可重试；**4xx 业务错误、鉴权失败不重试**（重试必然失败）。
- `get_retry_after_seconds(exc)`：优先读取供应商返回的 `Retry-After` 头。
- `backoff_delay(attempt, base, cap)`：**指数退避 + 全抖动**，避免惊群。

### 3.2 LLM 后端重试重构

涉及 `openai_backend.py`、`ollama_backend.py`、遗留 `client.py`、`embedding/base.py`：

- 仅重试可重试异常，4xx 直接抛出。
- 指数退避 + 抖动 + 尊重 `Retry-After`。
- **流式请求已产出内容后失败不再重试**（避免重复 token / 重复计费）。
- 流式 `try/finally` 关闭底层流，尽快释放连接；收到 `GeneratorExit` 时同样关闭。

### 3.3 `/chat/stream` 重构（`src/api/routes.py`）

- 新增"同步生成器 → 异步生成器"**线程桥接** `_bridge_sync_stream`：
  - 同步的 LLM / 检索 / Agent 迭代放入独立线程池，**不再阻塞事件循环**；
  - 主协程负责收事件、检查断开、编码 SSE。
- **断开即停**：检测到客户端断开或上层 `GeneratorExit` 时，跨线程 `close()` 底层同步生成器，触发 `GeneratorExit` 使 LLM 流 `finally` 关闭 HTTP 连接，停止 Token 消耗。
- 新增 `asyncio.Semaphore(LLM_MAX_CONCURRENCY)` 限制并发流数，防止打爆供应商 / 本地显存。
- 非 Agent 路径抽为同步生成器 `_iter_engine_stream`，与 Agent 路径统一走桥接，事件协议不变。

### 3.4 前端

`api/index.js`：

- SSE 按 `\n\n` **事件边界分帧**：半条事件留在 buffer 与下一数据包拼接，避免 TCP 分包截断 JSON。
- 损坏事件明确报错，**不再静默丢弃**。
- 支持 `AbortController` 取消。

`ChatInput.vue`：生成中显示红色**停止按钮**。

`ChatView.vue`：

- 停止生成 / 切换会话 / 新建会话时自动 `abort()`，中断未完成请求。
- 取消后保留已生成内容，不误报错误；空内容时提示"已停止生成"。

### 3.5 配置（`src/config.py`）

- 新增 `LLM_MAX_CONCURRENCY`（默认 8，可用环境变量覆盖）。

## 4. 适配性核对与并发安全修复

桥接改造使 `/chat/stream` 从"事件循环内串行"变为"线程池并发"，核对其与法律系统各组件时发现并修复了 3 处**既有并发隐患**：

| 位置 | 问题 | 修复 |
|------|------|------|
| `PgvectorStore` / `FAQCache` / `ConversationMemoryManager` / `ConversationStore` | 共享单个 psycopg2 连接且无锁，psycopg2 连接**非线程安全**，并发访问会 cursor 冲突 / 数据串扰 | 为每个类加 `threading.Lock`，所有使用连接的方法（含 `close`、`doc_count`）通过 `@_locked` 装饰器串行化；装饰器防御性支持绕过 `__init__` 的构造（兼容测试 mock） |
| `Bm25Retriever.load_index` | 直接 `with self._store._conn.cursor()` 绕过锁；懒加载并发会**重复构建索引**（10-20s），且索引构建与读取无锁 | 新增 `PgvectorStore.fetch_all_active_chunks()`（加锁公共方法），`load_index` 整体持锁、`search` 读取持锁 |
| `ArticleRouter._query_db` | 直接访问 `self._store._conn` 绕过锁 | 用 `self._store._lock` 包裹 DB 访问 |

其余核对结论：

- **双后端适配**：openai / ollama 两套后端 + 遗留 `client.py` 统一走 `retry.py` 策略，接口签名未变，`LLMAdapter` 注入路径不受影响。
- **双模式适配**：`AGENT_ENABLED` 开关下 Agent / RAG 两路径均走桥接，事件协议（`thinking/token/meta/clear/error`）与前端完全兼容。
- **死代码确认**：`PgvectorRetriever`（v1 旧表兼容）全项目无实例化使用，无需处理。
- **前端样式**：停止按钮所需 `--color-danger` / `--color-danger-hover` 已在 `App.vue` 亮 / 暗两套主题补齐。

## 5. 验证

### 5.1 全量测试

- 全量测试 **348 passed**。
- 唯一 error 为 `evaluation/scripts/smoke_test.py` 的既有 pytest 误收集问题（独立 smoke 脚本），与本次改动无关。
- 新增回归测试 `tests/test_retry_policy.py`（13 个用例）固化关键行为：
  - 重试判定（429/5xx/网络/超时可重试；4xx 不重试）
  - 退避抖动范围
  - 流式已产出后不重试 + `finally` 关闭流
  - 首 token 前 429 退避重试成功
  - 4xx 同步生成不重试

### 5.2 专项行为验证

通过临时验证脚本（验证后已删除）确认 7 项核心行为：

1. 重试判定 / 退避 / Retry-After 解析
2. 流式中途失败不重试 + `finally` 关闭流
3. 首 token 前 429 重试一次成功
4. 4xx 业务错误不重试
5. 桥接断开取消（断开后底层生成器被关闭）
6. **上层 `GeneratorExit` 关闭底层生成器**（验证中发现并修复了桥接 `finally` 未强制 close 的真实 bug）
7. 桥接正常流转

## 6. 遗留事项与建议

- **取消无法"瞬时"中断**：若模型正阻塞在网络等待，跨线程 `gen.close()` 的 `GeneratorExit` 要等该次 I/O 返回后才能生效（CPython 生成器语义限制）。对 OpenAI SDK 已在 `finally` 关闭流，网络返回后立即释放；彻底解决需换异步 SDK。
- **断开检测轮询间隔约 1s**：取消响应上限约 1 秒。
- **锁的串行化取舍**：FAQ 命中检查与记忆检索会把 embedding 调用包在锁内，多用户并发时这两处会毫秒级排队。对当前单 PG 实例、低并发咨询场景是正确取舍（避免连接竞态崩溃）。若未来并发提升，建议升级为 `psycopg_pool` 连接池后去除锁。
- **意图路由首字延迟**：`needs_retrieval` 对 ≤8 字短查询仍发一次完整 LLM 调用（已不阻塞事件循环），如需极致首字可后续改为纯规则路由。
- 遗留 `src/llm/client.py`（`LawLLM`）为旧版实现，本次已同步其重试策略；建议后续评估整体移除，避免双实现漂移。
