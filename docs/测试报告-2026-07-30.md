## 2. 失败用例追踪与闭环

### ① `test_api.py::TestHealth::test_health_ok` — 环境恢复后自愈 ✅
- **修复前**：503（本机 PG 未启动，health 探活引擎链时连接被拒）。
- **本轮**：PG 经 Docker 启动后通过。同批 3 个 `pg_required` 真实数据库用例（注册/登录/会话列表）也由 skip 转为通过。

### ② `test_step7.py::TestHallucinationGuard::test_low_score_docs_fail` — 测试对齐现行规格 ✅
- **根因**（git 溯源）：`MIN_SIMILARITY` 初始值 0.7（`cf07d81`，测试同期编写）；`9dbdd2c` 有意将默认阈值降至 0.4（`HALLUCINATION_MIN_SIM` 可覆盖），测试仍硬编码 0.55/0.60 旧分数。
- **处置**：判定为**测试未跟进规格变更**，修改测试为基于 `MIN_SIMILARITY` 动态取值（高于阈值 +0.01/+0.2 通过、低于阈值 -0.01/-0.05 拦截），后续调阈值不再需要改测试。
- **提交建议**：`test: 幻觉阈值测试对齐 9dbdd2c 的 0.4 默认值，分数改为动态推导`

### ③ `test_rewrite_api.py::test_rewrite_endpoint_precise_keeps_meaning` — 真实产品缺陷，源码修复 ✅
- **根因**：该用例走真实 LLM 改写链路。"刑法第232条是什么"被 DeepSeek 泛化为"触犯故意杀人罪 判处死刑"——**明确法条引用在改写中丢失**，违背 `rewrite.py` 自述设计原则（"仅做术语规范化，不改变原意"）。法条精确查找场景下会破坏召回精度。
- **处置**：在 `src/agents/rewrite.py::rewrite_query` 增加**精度护栏**——提取原句中的法条引用（`第X条` / 《法律名》正则），若改写结果未原样保留任一引用则回退原句：
```diff
+ _ARTICLE_REF = re.compile(r"第[0-9０-９零一二三四五六七八九十百千两]+条")
+ _LAW_REF = re.compile(r"《[^》]+》")
  ...
+ refs = _ARTICLE_REF.findall(query) + _LAW_REF.findall(query)
+ if refs and any(ref not in out for ref in refs):
+     logger.warning("改写丢失法条引用 %s，回退原句", refs)
+     return query
```
- **兼容性**：既有单测全部不受影响（`test_rewrite_strips_quotes` 的改写结果保留"第232条"故不放回退；口语化用例无引用不触发护栏）。
- **提交建议**：`fix: 改写丢失明确法条引用时回退原句，保证法条精确查找`
