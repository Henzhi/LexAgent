## 二、判定方法（这一步决定了结论可信度）

初版靠"文件名 + 文件头"下结论，被真实数据打脸两次，最终方法改为**内容证据**：

1. 按 `metadata.paragraph_index` 还原原文顺序后拼接（chunk 的 `id` 是 uuid 无语义顺序，按 uuid 拼接会把条文拆碎 → 伪差异）；
2. 抽出 `{条文号 → 正文}`，**剥掉【罪名】标题**（不同爬虫来源的排版噪声，不剥会把同一版本判成两个版本）；
3. 阿拉伯/中文条号归一（`第165条` ≡ `第一百六十五条`）；
4. 逐条比对 → 零差异即重复入库，有差异即真实版本差异，**差异条数即影响面**。

| 曾被误判 | 真实情况 |
| :--- | :--- |
| 治安管理处罚法：以为是"2005/2012 旧版 + 2025 修订版" | **144 条正文 100% 一致** → 纯重复入库（磁盘源文件是旧版，但入库的是新版内容，title 与内容不对应，属另一处数据治理问题） |
| 刑法：初判差异面很大 | 剥掉【罪名】后**仅 8 条实质差异** |
| 公司法：以为有三份不同版本 | 305ch 与带尾空格的 306ch 是同一版本；另一份 207ch/49 条是**残缺副本** |

### 刑法差在哪（最危险的一例）

无后缀版的沿革止于 **2020-12-26**（刑法修正案十一），(2023修正) 版止于 **2023-12-29**（修正案十二）。逐条比对 505 条中有 8 条实质差异，均为修正案十二涉及条文，例如：

- **第 165 条**：新版在"国有公司、企业的**董事、监事、高级管理人员**"之外，新增"**其他**公司、企业的董事、监事、高级管理人员违反法律…"——即民企腐败入刑。旧版问"私营企业经理同业经营获利是否构成犯罪"会答"不构成"，正确答案在新版是"构成"。
- **第 393 条**：单位行贿刑期由「5 年以下」改为「3 年以下 + 情节特别严重 3~10 年」——量刑区间完全不同。

每一条都是量刑依据，召回错版本即答错。

## 四、重复/残缺入库（19 份 / 2365 chunks）

同一版本被写入多份（不同批次 rechunk），典型：

| 分组 | 情况 |
| :--- | :--- |
| 公司法 | 305ch 与带尾空格的 306ch（文件名尾部空格，被当成两部不同的法各自 ingest） |
| 证券法 | 281ch 与 282ch 正文逐条一致 |
| 宪法 | (2018修正) 与（2018年修正文本）143 条全部一致 |
| 治安管理处罚法 | 157ch 两份 144 条全部一致 |
| 立法法 / 监察法 / 行政复议法 / 道交法 | 各有一份带尾空格的重复文档 |

影响：同一条款的两份近似 chunk 在 RRF 融合与相邻扩展中会**双双占据召回前排**，挤掉来源多样性；同时浪费 embedding 与存储。

## 五、处方

### ✅ 前置认识（核实时更正）

初版报告称「`documents.status` 没有任何检索代码在读」，**核实时发现不成立**：`PgvectorStore.search()` 与 `article_router` 早已带 `d.status = 'active'` 谓词——代码早就就位，只是从来没人往这个字段写过值（全库恒为 `active`），等于半截功能。因此本治理**只需填数据、无需改检索主链路**。

核实中发现唯一遗漏：`law_centroids._load_rows()`（法名质心构建）没有过滤 status，会让失效版本混进质心、稀释法名推断权重——已补上，并加守护测试防止再漏。

### Step 1 — 判定（已完成）

`evaluation/scripts/check_law_version_conflicts.py`，默认 dry-run，产出 `evaluation/data/law_version_verdicts.csv|json`。26 项 DB-free 单测在 `tests/test_check_law_version_conflicts.py`。

### Step 2 — 写短语态（**已执行，2026-09-07 15:10**）

```
uv run python evaluation/scripts/check_law_version_conflicts.py --apply
```

执行结果：备份 `evaluation/data/documents_status_backup_20260907_151051.json`，写回 33 行。

| 项 | 执行前 | 执行后 |
| :--- | :--- | :--- |
| `status=active` 文档 | 1039 | **1012** |
| `status=superseded` | 0 | 8 |
| `status=duplicate` | 0 | 19 |
| **可检索 chunks** | 53235 | **49357**（−3878） |

抽查验证：刑法第 165 条现在**只命中 (2023修正) 版**，且含「其他公司、企业的董事、监事、高级管理人员」——旧版已不可召回。

- 自动导出受影响行备份到 `evaluation/data/documents_status_backup_<ts>.json`；
- `superseded` → `status='superseded'` + `superseded_by=<保留版 id>`；
- `duplicate` / `partial` → `status='duplicate'`；
- `current` / `keep` → 保持 `active`；`ambiguous` 不动。
- **不删任何行、不删任何 chunk**，回滚只需照备份 JSON 改回 `active`。

### Step 3 — 补漏 + 守护（**已执行**）

- `law_centroids._load_rows()` 补 `d.status = 'active'`（法名质心不再被失效版本稀释）；
- 新增 `tests/test_doc_status_filter.py`：捕获真实执行的 SQL，断言三条检索路径都带 status 谓词——**将来新增检索路径漏过滤会直接红**；
- 新增标题归一测试，防尾空格重复入库回归。

### Step 4 — 管道长效（**已执行**）

`IngestionPipeline` 新增 `normalize_document_title()`：`run()` 与 `ingest_text()` 在**查重之前**先归一标题（去首尾空白、压缩内部空白），消除「文件名尾空格 → 当作两部法重复入库」的根因。

后续仍可加（未做）：入库写入版本时间戳与失效关系、同一 base 法名只允许一个 active 的冲突告警。

## 六、验证检查点（每条可复现）

1. `SELECT count(*) FROM documents WHERE status IN ('superseded','duplicate')` == 27（8 + 19）；
2. 抽查三问：①「私营企业经理同业经营获利是否构成非法经营同类营业罪」→ 必须引刑法(2023修正)第 165 条且含"其他公司、企业的董事、监事、高级管理人员"；② 单位行贿量刑 → 必须是「3 年以下 + 情节特别严重 3~10 年」；③ 宪法条文 → 不得再出现 1982 年版本；
3. 重跑检索评测 multi100，确认 Hit@5 不低于 92%（剔除重复副本后应不降）；
4. 新增守护测试：同一 base 法名不得存在两个 `status='active'` 的非白名单文档。
