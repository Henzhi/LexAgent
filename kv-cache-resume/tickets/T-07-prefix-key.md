## 要做出什么

给定一次请求（模型 + 量化 + 完整 token 序列），算出一个**稳定的缓存键**；同时提供一组**归一化约定**，让「逻辑上相同的 prompt」不会因为无害的序列化差异算出不同的键。

正面：同前缀必命中。
反面：**任何一处真实差异都必须判 miss**——宁可重算，绝不用错的 KV 产出错的结果（REQ-W2）。

## 范围

**做**

- `kv_cache/prefix.py`
  - `compute_key(model_id, quant, token_ids) -> str`：`sha256(model_id ‖ quant ‖ token_ids)[:16]`
    - **编码要定死**：分隔符、`token_ids` 的序列化方式（建议紧凑二进制或定长拼接，不要 `repr(list)`——`str([1, 2])` 与 `str([1,2])` 不同会导致同输入不同键）
  - `tokenize(messages)` 接口：本票只定签名 + 一个可注入的实现（真实 tokenizer 由调用方给），因为策略层不该自己管模型词表
  - `canonicalize(messages)` —— **R1 的缓解措施**：对已知不稳定字段做归一化
    - JSON key 顺序稳定（`sort_keys=True` 那类处理）—— **直接相关**：LexAgent 的工具 schema 由 pydantic 从类型注解推导，key 顺序可能变
    - 空白/换行归一（chat template 渲染差异）
    - **不稳定字段检测**：时间戳 / 随机 ID / 动态内容 → 检测到就**拒绝缓存该请求**（而不是硬归一化后假装安全）
- `tests/test_prefix.py`
  - 幂等：同输入两次算出同键
  - **AC7 三组扰动样本**，每组都必须判 miss：
    1. schema JSON key 顺序变动
    2. 空白 / 换行差异
    3. 时间戳变动
  - REQ-U2 前置守护：`model_id` 变 → 键必变；`quant` 变 → 键必变
  - `canonicalize` 的正面用例：等价输入归一化后 token 序列一致

**不做**

- 不实现真实 tokenizer（模型相关，留给接入侧）
- 不做存储 / 不碰磁盘（那是 T-08）
- 不做「模糊匹配」「前缀截断复用」—— 本票是**精确匹配**语义，SPEC 的设计就是这样

## 验收清单

- [x] **AC7：三组扰动全部判定为 miss**，且断言**没有使用旧 KV**
      —— 用一个 `{key: payload}` 的假索引承载「旧 KV」，断言三组扰动后 `lookup` 返回 `None`
      （即真的走了 miss 分支，不只是「键变了」）
- [x] 幂等：同输入两次计算结果相同（含 **bytes 级**比较 —— `encode_key_material` 直接对比）
- [x] REQ-U2 守护：模型标识或量化变化 → 键必变；空 `model_id` / 空 `quant` 直接拒绝
- [x] 不稳定字段（时间戳 / UUID / 长 hex / 内存地址）被**检测并拒绝缓存**，
      有单测覆盖「检测到 → 抛 `PrefixMismatch`」路径
- [x] 代码里没有 `repr()` / `str()` 之类的隐式序列化（用显式编码，避免同输入不同键）
- [x] `docs/phase1-design.md` 的归一化清单与实际实现一致（**7 条规则 + 6 条明确不做 + 4 条拒绝规则**）

## 落地说明：三个必须写下来的判断

### 1. AC7 与 R1 表面冲突，靠「归一化改输入、从不已改写键」化解

AC7 要求「空白 / schema key 顺序扰动必须判 miss」，R1 的缓解措施却说「对空白做归一化」。
两者不能同时按字面实现，本票把界划在**层**上：

- `compute_key()` 对 token 序列**一个 token 都不归一化** → 扰动到达 token 层必然 miss（AC7 成立）
- `canonicalize()` 是**上游 opt-in 的输入改写**，其输出即发送内容 → 等价写法折叠后逐字节相同，
  命中的确实是同一段前缀（R1 成立）

**为什么不能让「键归一化、发送原始文本」**：那样键会命中一份属于别的前缀的 KV ——
restore 返回 200、答案却是错的，而且**静默**。这正是 REQ-W2 要防的事。
已写入 `docs/phase1-design.md` §4.0 与 `prefix.py` 模块 docstring。

### 2. 验收项「没有 `repr()`/`str()` 隐式序列化」用**行为断言**而不是 grep 源码

grep `repr(` 会被注释和等价写法骗过。改成本票实际用的是三组**碰撞用例**：
`("ab","c")` vs `("a","bc")`、`[1,2]` vs `[12]`、`[1,2]` vs `[2,1]` ——
这些在朴素 `str()` 拼接下都会算出同一个键，能挡住它们才说明编码真的无歧义。

### 3. 不稳定字段检测的**误报就是性能事故**，故主动否决了三条候选规则

`UNSTABLE_PATTERNS` 是数据（加规则只改元组）。以下是**被明确否决**的候选及理由：

| 否决的候选 | 理由 |
| :--- | :--- |
| 裸 10/13 位 epoch 数字 | 法律语料里 11 位手机号、18 位身份证号、长编号极多，误报会让**本该命中的请求全部拒绝缓存**，直接打穿 AC4（命中率 ≥99%） |
| 裸日期 `2020-01-01` | 合同签订日 / 法条生效日几乎全是**内容**而非注入的当前时间 |
| 纯数字长串 | 同上；由 `hex_id` 的「必须含 a-f 字母」在正则层排除 |

口径：「宁可重算」只是慢一次；「宁可不缓存」是收益归零。两者不能混为一谈。
判据是 `test_no_false_positive_on_legal_text`（7 个法律语料样本必须零命中）。

> ⚠️ 附带结论：`iso8601_datetime` **强制要求带时间部分**。将来若有人想放宽成「裸日期也算不稳定」，

## 落地时与票面不符之处（已回改文档）

1. **AC7 第 2 组（空白）的处置需要区分两种空白**：改变 token 序列的（AC7 → miss）
   与可证明等价的序列化差异（R1 → 折叠）。票面把它们并列了，实现按 §4.0 的界拆开，
   并在设计文档 §4.2 列出「不做归一化」的清单（不合并行内空格、不删行首缩进）。
2. **自由文本 `content` 里内嵌的 JSON 不重排**：无从判断散文里哪一节是 JSON，硬猜会改坏文本。
   代价是该形态下 key 顺序变化仍判 miss（偏安全）。已补 `test_json_inside_free_text_is_not_reordered`
   把这个边界钉住，避免将来误以为「所有 JSON 都被归一化了」。
3. **`quant` 不做大小写折叠**：折叠会让 `Q4_K_M` 与 `q4_k_m` 共用键，方向是反的。
   大小写统一由 `config.KV_QUANT_CHOICES` 负责，本层把它当不透明版本串。
   （旁注：SPEC §4.3 的 meta 示例写的是 `Q4_K_M`，而 `KV_QUANT_CHOICES` 全小写 ——
   这处不一致属 T-08 落 meta 时的问题，已在此记录，本票不擅自统一。）

## 备注

- **本票最容易踩的坑是「看起来对」**：`hash(str(token_ids))` 能跑、大多数时候也能命中，但在 Python 版本 / 分隔符 / 空格细节上会悄悄出错。键必须每次都能复现，所以序列化方式要在代码里写死并配注释解释。
- AC7 的第 3 组（时间戳）是**唯一一个无法靠归一化解决**的：时间戳一变，token 序列就真变了，缓存就不该命中——除非把时间戳从 prompt 里挪走（那是上游的事）。本票要做到的是「**正确判 miss**」，不是「想办法命中」。
- 归一化清单写进 `docs/phase1-design.md` 是给 T-13 验收用的：验收时按清单逐条构造样本。
