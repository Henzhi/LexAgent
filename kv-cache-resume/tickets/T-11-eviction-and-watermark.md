## 要做出什么

两件事，防止这个 spike 把磁盘吃光：

1. **容量上限**：目录占用永远不超过 `KV_MAX_BYTES`，条目数不超过 `KV_MAX_ENTRIES`，超了就按 LRU 淘汰
2. **磁盘水位保护**：可用空间低于 `KV_MIN_FREE_BYTES` 时停止落盘并告警，空间回来自动恢复

R2 明确说这是必须做的——KV 文件是**线性增长的**（4K token ≈ 219MB@27B，50K ≈ 2.7GB），没有上限就是定时炸弹。

## 范围

**做**

- `kv_cache/eviction.py`
  - `enforce_limits()`：超 `KV_MAX_BYTES` **或** 超 `KV_MAX_ENTRIES` → 按 `last_used_at` 从旧到新淘汰，**淘汰到低于上限为止**（注意是「低于」不是「等于」，避免边界上反复触发）
  - **淘汰顺序**：先摘 index 条目 → 再删文件（与 T-08 定的方向一致：`index` 是最后真相源，中断只留孤儿，由 T-08 启动扫描回收）
  - **在途保护**：正在被 restore 使用的条目**不可淘汰**。用一个简单的引用于集合标记即可（spike 不必上引用计数，但要写清这个简化）
  - `free_bytes(path)` + **水位状态机**（REQ-W4）：
    - 低水位 → 停止落盘 + 告警
    - 恢复 → 自动续写（**不是等重启**，要显式恢复）
    - 状态转换要被遥测看到（T-12）
  - `persist` 前的前置检查：先 `enforce_limits()` + 水位判断，再决定写不写（与 T-10 留的 hook 点对接）
- `tests/test_eviction.py`（**全部用假文件 + 假 `stat`，不写真实大文件**）
  - LRU 正确性：被命中过的条目比未命中的后淘汰
  - 上限边界：淘汰后占用 ≤ 上限；恰好在边界上不反复触发
  - 两条上限分别触发（字节数 / 条目数）
  - 在途恢复中的条目不被淘汰
  - 水位：低 → 停写 + 告警；恢复 → 自动续写（状态机断言）
  - 淘汰中断：在删文件前注入异常 → 断言不产生「index 有、文件无」

**不做**

- 不做跨进程并发淘汰（spike 定位）
- 不做用户可配的淘汰策略插件化（固定 LRU 即可）
- 不真删用户数据 —— 本票只处理自身缓存目录

## 验收清单

- [ ] **AC6 / REQ-S1**：写入超量数据后，`enforce_limits()` 返回时目录占用 ≤ `KV_MAX_BYTES`（立即成立，不是「下次再说」）
- [ ] **REQ-S2**：条目数 ≤ `KV_MAX_ENTRIES`，且两条上限各自单独触发时行为正确
- [ ] **LRU 正确性**：命中过的条目存活时间更长（构造序列断言淘汰名单）
- [ ] **REQ-W4**：水位低 → 停写 + 告警；水位恢复 → **自动**续写（不需要重启，状态机断言）
- [ ] 在途恢复中的条目未被淘汰（断言该 key 仍在索引里）
- [ ] 淘汰中断不产生「index 有、文件无」的状态
- [ ] 测试不依赖真实磁盘剩余空间（可用假 `stat`），`pytest` 在 CI 可跑

## 备注

- `KV_MAX_BYTES` 的默认值**不要在 T-05 拍脑袋定**，本票落地后按 T-04 的 `bytes/token` 实测回填，并在代码注释里写明依据与算例（例如「按 3B 模型实测 X KB/token，留 N 条 4K 上下文 ≈ Y GB」）。
- 水位保护与 T-10 的落盘路径要**串起来**：`persist` 必须先过水位检查。这条在 T-10 完成后再回来接线，接完补一条端到端断言（停写期间不产生新文件）。
- 与 SPEC §4.1 的对照项是 LexAgent 事件日志的 TTL 600s —— 这边是 TTL + LRU + 目录上限三重。**不再加 TTL**（KV 的价值随时间衰减远低于事件日志，且 LRU 已经覆盖），若要加需先回改 SPEC。
